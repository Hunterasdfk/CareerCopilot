# CareerCopilot 项目规则

## 项目定位

这是一个面向中国大学生秋招场景的开源求职助手。

核心流程：
岗位导入 → 简历匹配 → 投递辅助 → 状态追踪 → 邮件提醒 → 回复草稿。

## 当前阶段

当前只进行 MVP 0.1 的需求设计和任务拆解。

在用户明确要求开始开发前：
- 不生成业务代码；
- 不安装依赖；
- 不连接 Gmail；
- 不操作招聘网站；
- 不创建真实账号；
- 不执行自动投递。

## MVP 0.1 范围

MVP 0.1 管理的是 opportunity（求职机会），不保证每条记录都是具体 job。只有获取到具体岗位后，才能执行“每家公司至少推荐三个具体岗位”。

只实现以下业务闭环：
1. 导入包含 campaign 和 job 两类记录的 XLSX 或 CSV 求职机会表；
2. 识别公司、机会类型、显示名称、申请链接及可用的岗位信息；
3. 展示全部求职机会，不得因为 Top 3 规则隐藏其他记录；
4. 支持筛选和手动标记优先级；
5. 对每家公司进行候选机会覆盖检查：
   - 机会充足时，允许用户至少保留 3 个候选机会；
   - 不设置最多 3 个的上限；
   - 少于 3 个时显示数量缺口；
   - campaign-only 的公司显示“需进入招聘官网选择具体岗位”；
6. 点击按钮打开公告链接或申请链接；
7. 手动记录投递状态。

## 后续版本

MVP 0.2：
- 简历与岗位匹配；
- Playwright 辅助填写；
- 最终提交前必须由用户确认。

MVP 0.3：
- Gmail 邮件获取；
- 招聘邮件分类；
- 重要邮件提醒；
- 生成回复草稿；
- 禁止默认自动发送邮件。

## 安全要求

- 不绕过验证码；
- 不实现反检测或账号风控规避；
- 不自动捏造求职信息；
- 不默认点击最终提交；
- 不默认自动发送邮件；
- 密码、Token、API Key 和真实简历不得提交到 GitHub；
- 真实工作簿不得提交到 GitHub；
- 真实数据应放在仓库外部，或放入被 .gitignore 完整排除的 data/private/；
- 匿名示例数据可以提交，但必须使用虚构公司、岗位和 example.com 链接；
- 所有可能产生外部影响的操作必须经过用户确认。

## 技术原则

预定技术栈：
- Python 3.11；
- Streamlit；
- SQLite；
- pandas/openpyxl；
- 后续使用 Playwright；
- 后续使用 Gmail API；
- 后续使用 Apprise。

开发要求：
- 每次只完成一个小任务；
- 修改前先说明计划；
- 修改后运行测试；
- 不擅自扩大需求；
- 关键业务逻辑必须有测试；
- 优先采用许可证清晰的依赖；
- 输出和文档以中文为主，代码命名使用英文。

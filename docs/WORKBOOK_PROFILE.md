## 3. 中国大陆同一工作表内的历史字段布局（实证）

对 8712 条非表头行做 F×G 语义交叉（仅类别计数，不打印真实值）：

| F 语义 \ G 语义 | cohort(届次/年份) | city(城市) | other | empty |
| :--- | :--- | :--- | :--- | :--- |
| **kw**（F=招聘类型关键词，如秋招全职/春招全职/日常实习/暑期实习） | **2114** | 0 | 0 | 0 |
| **job**（F=具体岗位名称） | 34 | **4569** | 524 | 0 |
| **other**（F 既非关键词也非典型岗位名） | 121 | 1057 | 209 | 0 |
| **empty** | 0 | 0 | 0 | 84 |

**结论（强证据）**：

1. **新版 campaign 布局**：F 为招聘类型关键词 + G 为届次 → 2114 行，完全自洽。
2. **旧版 job 布局**：F 为具体岗位名称 + G 为工作城市 → 4569 行，完全自洽。此时 H/I/J 列语义相对表头**发生错位**（按旧版：H=招聘类型、I=招聘届次、J=学历要求），**不能沿用 row1 标签**。
3. **必须人工确认**：F=other（1387 行）、F=job 但 G≠city（34+524 行）无法可靠判定，不得强行推断。

> row1 表头标签（F=招聘岗位、G=招聘对象（届次）、H=学历要求、I=招聘类别、J=工作城市）描述的是 campaign 布局语义；对 job 布局行不适用。

## 3.5 补充验证：中国香港 D–H 与 美国 F/G 布局复核

| H | 学历要求 | job_description 1380、education_requirement 1343、other 801、target_cohort 399 |

F×G 交叉（top）：

| F 语义 | G 语义 | 行数 |
| :--- | :--- | :--- |
| recruitment_type | target_cohort | 1368 |
| **education_requirement** | **job_description** | **923** |

**结论：中国香港存在多种布局（互斥分类，合计 = 3923 行）**：

1. **候选标准布局**（1368 行）：F=招聘类别(recruitment_type)、G=届次(target_cohort) —— 与表头一致。基于 F×G 签名判定，属**候选**布局，最终需人工复核。
2. **候选错位布局**（923 行）：F=学历(education_requirement)、G=岗位描述(job_description) —— 与表头**严重错位**；且 E 列在 2168 行中承载届次（表头为“岗位描述”），证明列语义整体漂移。基于签名判定，属**候选**布局，最终需人工复核。
3. **无法可靠判断**（1632 行 = 3923 − 1368 − 923）：F=RT&G=other 772、F=edu&G=other 719、以及其他 F/G 歧义组合，需导入预览人工确认。

> 三类合计 1368 + 923 + 1632 = 3923。香港**不得声称全部记录已可靠识别**：上述“标准/错位”仅为基于签名的**候选布局**，最终 record_type 与列映射须经导入预览人工确认。香港不得继续标记为完全静态映射。香港与新加坡**不同构**（新加坡 F 100% 为 recruitment_type，见 §3.5.3）。

## 4. 字段类型观察

- **日期字段**：A（更新日期/更新时间）、B（开岗日期，仅中国大陆）、K（截止时间/截止日期）、低年级全球版 I（毕业时间）、低年级公司官网**无日期列**。日期单元格在 styles.xml 中对应 68 个日期 XF；部分日期也可能以文本存储，解析器需同时兼容数值日期与文本日期。
- **链接字段**：均以 `http` 开头存为单元格文本值；中国大陆有公告链接(M) + 投递链接(N) 两个 URL 列；其余工作表只有一个 URL 列（列位因表而异：J / K / L / H）。
- **文本字段**：企业名称、岗位名称、岗位描述、行业、招聘类别、届次、学历、城市等均为 sharedStrings 文本。

- **中国大陆**：所有行的整行原始单元格（含 A–N 及任何超界列），尤其 job 布局行与无法判定行，便于回溯与人工复核。
- **所有工作表**：未被映射到标准字段的列（如企业性质 C、公司规模 C、岗位描述 E、申请限制 J 等）整体保留为 JSON 文本。
- **无效/待确认记录**：整行原样保留到 `raw_data`，`record_type=unknown`，不直接入库业务字段。
- **原始列位信息**：`source_sheet` + `source_row` 必须写入，确保可回溯到源工作簿具体位置。

## 8. campaign 与 job 的判定依据（汇总，已按补充验证修订）

- 中国大陆：F ∈ {秋招全职, 春招全职, 日常实习, 暑期实习, 秋招实习, 春招实习, 实习生招聘, …} **且 G 为届次** → `campaign`；F 为具体岗位名称 **且 G 为城市** → `job`；其余 → `unknown`（人工确认）。
- 中国香港：**存在多种布局**，不得仅按表头静态映射。标准布局（F=招聘类别 & G=届次）与错位布局（F=学历 & G=岗位描述）须分别检测；D 列有具体岗位名称 → `job`；歧义行 → `unknown`（人工确认）。
- 美国：**存在 F/G 字段交换**。标准（F=届次 & G=学历）→ 按表头映射；交换（F=学历 & G=届次）→ 互换映射；F 或 G 歧义 → `unknown`（人工确认）。H 列有具体岗位名称 → `job`。
- 英国 / 新加坡：F 列稳定（招聘类别），G 列存在少量歧义子集（英国约 540、新加坡约 155 行）→ `unknown`（人工确认）；D 列有具体岗位名称 → `job`。
- 低年级-全球版 / 公司官网：本质偏项目入口（campaign-like）；F=职位名称/项目名称有具体岗位时才标 `job`，否则 `campaign`。
- **不确定的一律标 `unknown`，不强行推断**。

## 9. 解析阶段约定（补充，不修改原统计）

本节记录 `layout_detector.py` / `opportunity_importer.py` 在解析阶段遵循的约定，是对 §3–§8 统计结论的实现层补充。

### 9.1 source_row 行号约定

- `source_row` 使用原 XLSX/CSV 的**物理行号**（1-based）；
- 表头为第 1 行；
- 第一条数据为第 2 行；
- 空行可以不输出记录，但**必须占用物理行号**；
- 空行后的记录继续使用真实行号，**不得重新连续编号**；
- `parse_sheet` 使用 `enumerate(df.iterrows(), start=2)` 按行位置计算物理行号，**不依赖 DataFrame index 可转 int**（支持自定义或字符串 index）。

### 9.2 候选布局临时结构

香港/美国候选布局在解析阶段输出以下临时结构，**不得直接入库**：

| 字段 | 值 | 说明 |
| :--- | :--- | :--- |
| `record_type` | `"unknown"` | 始终为 unknown，`compute_dedupe_key` 返回 None |
| `layout` | 候选布局标签 | 如 `hk_standard_candidate`，保留候选签名 |
| `needs_confirmation` | `True` | 标记需人工复核 |
| `suggested_record_type` | `"job"` / `"campaign"` / `None` | 保守建议；可为空（`None`），表示不提供最终建议 |
| `suggested_fields` | `{字段: 取值}` | 暂定字段映射，仅为建议，不得入库 |
| `raw_data` | 完整原始行 | 整行单元格保留，键为列字母 |

> 顶层**不写** `company_name` / `job_title` / `target_cohort` 等最终业务字段。确认操作属任务 5。

### 9.3 大陆 F=job 与 F=other 区分

`_classify_mainland_f()` 不再把所有非招聘关键词的非空值都判为 job：
- 明确招聘类型关键词 → `kw`；
- 通过 `_is_job_title_like()`（含工程师/开发/分析师/实习生/管培生/经理/专员/助理/顾问等关键词）→ `job`；
- 其他非空文本（如"其他类别/综合招聘信息/招聘公告/多岗位/不限/可议"）→ `other`；
- 空值 → `empty`。
- **F=other + G=city 不会直接变成 job**（标 `unknown`）。

### 9.4 英国/新加坡独立招聘类型规则

英国/新加坡 F 列使用 `_is_uk_sg_recruitment_type`（非空且非日期/URL/届次/学历即可），**不复用大陆 `_RECRUITMENT_KEYWORDS` 白名单**：
- 支持 `Graduate Programme` 等招聘类型文本；
- F=本科或 F=2026届 等明显错位值 → `unknown`；
- G 为届次时正常映射；G 歧义时标 `unknown`。

### 9.5 香港 suggested_record_type 保守判定

候选布局的 `suggested_record_type` 不再"D 非空即 job"：
- D 通过 `_is_job_title_like()` → `suggested_record_type="job"`；
- D 为空 → `suggested_record_type="campaign"`；
- D 非空但属于招聘类型/届次/学历/描述或无法判断 → `suggested_record_type=None`（不提供最终建议）；
- `record_type` 始终保持 `unknown`，`needs_confirmation=True`，`raw_data` 完整保留。

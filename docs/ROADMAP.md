# CareerCopilot 项目路线图 (ROADMAP)

## 1. 阶段规划

项目发展将分为三个主要阶段，逐步实现从数据管理到智能辅助的进化。

### **Phase 1: MVP 0.1 - 岗位管理看板与公司覆盖检查 (当前阶段)**

*   **核心目标**: 解决岗位信息管理混乱、投递状态追踪困难的问题。构建一个稳定的、功能闭环的桌面级工具，并引入“公司覆盖检查”概念。
*   **主要特性**:
    *   岗位信息导入 (XLSX/CSV)，支持去重和导入报告。
    *   岗位列表浏览与多维筛选。
    *   **候选清单与公司覆盖检查**：始终保留并展示每家公司全部机会，按优先级排序并默认突出前 3 个（不截断、不设上限）；不足 3 个时显示数量缺口。
    *   一键打开外部投递链接（仅跳转，不自动标记状态）。
    *   **精细状态追踪**：严格区分 `opened` (已打开) 和 `applied` (已投递)。
*   **暂不处理**:
    *   简历解析与智能匹配。
    *   任何形式的自动化表单填写。
    *   电子邮件集成。
*   **技术重点**:
    *   Streamlit 界面开发。
    *   SQLite 数据库设计与交互。
    *   Pandas 数据处理与字段映射逻辑。
    *   去重逻辑与状态机实现。

### **Phase 2: MVP 0.2 - 智能筛选与半自动投递**

*   **核心目标**: 引入简历信息，实现岗位与简历的智能匹配，并通过 Playwright 辅助用户完成表单填写，进一步降低重复劳动。
*   **主要特性**:
    *   **简历上传与解析**: 支持 PDF/Word 格式简历的上传与解析，提取核心技能和关键词。
    *   **智能匹配与推荐**: 计算简历与岗位描述的相似度，给出匹配度评分。**此阶段才真正实现基于匹配度的智能推荐**：对每家公司的全部岗位评分并排序，**默认突出前 3 个高匹配度岗位（不截断，不设上限）**。
    *   **半自动投递**: 启动 Playwright 浏览器尝试填写表单，在最后一步提交前暂停，由用户手动点击。
*   **暂不处理**:
    *   完全无人值守的全自动投递。
    *   复杂的验证码识别。
*   **技术重点**:
    *   简历解析库。
    *   文本相似度算法。
    *   Playwright 与 Streamlit 的集成。
    *   处理不同招聘网站的 DOM 结构差异。

### **Phase 3: MVP 0.3 - 邮件智能处理与通知**

*   **核心目标**: 打通求职信息闭环，自动监听邮箱，分类整理招聘邮件，并在关键时刻主动通知用户。
*   **主要特性**:
    *   **Gmail 集成**: 用户授权后，系统定期扫描 Gmail 邮箱。
    *   **邮件分类与自动更新**: 识别关键邮件（笔试、面试、Offer），自动更新岗位状态。
    *   **智能回复**: 基于邮件内容和用户简历，生成礼貌的回复草稿。
    *   **多渠道通知**: 通过 Apprise 实现多渠道通知。
*   **暂不处理**:
    *   自动发送邮件（所有回复都必须由用户手动确认）。
    *   其他邮箱服务商的集成。
*   **技术重点**:
    *   Google Gmail API。
    *   Apprise 通知库集成。
    *   邮件内容解析与分类算法。

## 2. 主要风险与应对

*   **风险 1: 招聘网站的反爬与风控机制 (MVP 0.2)**
    *   **应对**: 严格遵循“最终提交前必须由用户手动确认”原则，不主动对抗风控。

*   **风险 2: 简历解析的准确性 (MVP 0.2)**
    *   **应对**: 提供简历解析结果的预览和手动修正功能。

*   **风险 3: 邮箱 API 的授权与稳定性 (MVP 0.3)**
    *   **应对**: 提供清晰的图文教程，实现健壮的 Token 刷新机制。

*   **风险 4: 本地数据的安全性**
    *   **应对**: 文档中明确提醒用户定期备份数据目录。

*   **风险 5: 公司岗位覆盖度不足 (MVP 0.1)**
    *   **描述**: 用户可能导入的岗位数据不全，导致某些重点公司的岗位数量不足 3 个。
    *   **应对**: 系统在候选清单视图中提供显眼的提示，督促用户去该公司官网或其他渠道挖掘更多岗位。
